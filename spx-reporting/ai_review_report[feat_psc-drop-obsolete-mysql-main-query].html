    问题

    _entity_where 在新增的多值 driver 过滤分支里，直接把任务载荷中的 drivers 做 int(d) 转换并拼进 SQL：parts.append(_in_or_eq("a.driver_id", [str(d) for d in sorted({int(d) for d in drivers})]))。

    这里没有任何异常兜底，且 drivers 明确来自异步任务的 filters，属于不可信输入。

    后果

    只要 filters["driver"] 中混入一个非整数字符串，导出任务就在构造 WHERE 子句阶段抛出 ValueError 并失败，形成可被任意任务提交方触发的拒绝服务；

    批量值场景下一个脏值就能让整份导出不可用。

    怎么改

    在 _entity_where 里对 drivers = _values(filters, "driver") 的每个元素做显式校验，并在非法值出现时返回受控错误而不是让 int(d) 直接抛异常。

    至少应在拼接前过滤或拒绝非十进制整数字符串，例如：

    raw_drivers = _values(filters, "driver")
validated_drivers: list[str] = []
for d in raw_drivers:
    s = str(d).strip()
    if not s.isdigit():
        raise ValueError(f"invalid driver filter: {d}")
    validated_drivers.append(s)
if validated_drivers:
    parts.append(_in_or_eq("a.driver_id", sorted(set(validated_drivers))))

    这样既能保留数值过滤，又不会因为单个非法值把整个任务打崩。

    怎么验

    构造一个导出任务，filters 中传入 {"driver": ["12345", "abc"]}，执行 _entity_where 或完整导出流程；

    修复前任务会因 int("abc") 抛异常失败，修复后应返回明确的参数错误，且不会生成半截 SQL。
