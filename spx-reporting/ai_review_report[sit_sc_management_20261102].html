    问题

    MR 描述原文把交付范围写成“Async parcel-detail export via job-consumer sc_management_dashboard_pressure_detail”，说明站点压力明细导出应走异步 job-consumer；

    但本次实现的模块说明明确写成“excel.py - XLSX writer for the volume download and /pressure/download” ，并且 README 的 endpoint index 也把 /pressure/download 作为页面接口暴露，表明当前实现提供的是同步下载接口而不是异步任务消费链路。

    diff 中虽有 pressure_constants.py 里的 REPORT_CODE_PRESSURE_DETAIL = "sc_management_dashboard_pressure_detail" 注释提到 job-consumer，但从当前材料可见的实际对外实现仍是 /pressure/download 同步导出，与 MR 描述的交付方式不一致。

    后果

    当站点压力明细数据量较大时，请求会在 API 进程内直接生成导出结果，而不是交给异步 job-consumer 处理，可能导致页面等待时间、请求超时行为和预期验收方式不一致；

    同时如果前端或验收按异步导出流程联调，也会发现接口形态对不上。
