    MAJORL432-434异常处理🔄 行号已纠正
    问题

    QueryEngine.estimate_row_count 在提交导出前新增了一次 COUNT(*) 预估，但当 self._execute(template, sql, bind_params, timeout_ms=timeout_ms) 返回空结果时，代码直接 return 0。

    这会把“查询执行异常/驱动异常导致没有结果集”和“真实结果就是 0 行”混为同一种返回值，调用方 routes/platform.export_query 无法区分预估失败与真实空结果。

    后果

    一旦 Doris/数据库驱动在 COUNT(*) 查询中出现异常但被 _execute 以空 DataFrame 形式返回，export_query 会把该请求当成小结果集继续提交 consumer，导致本应在 20 秒内被拒绝的高代价导出继续进入异步执行，最终在 consumer 侧长时间占用资源甚至再次触发 900 秒超时，形成可被普通导出调用者反复触发的资源消耗风险。

    怎么改

    修改 QueryEngine.estimate_row_count，把 df is None 或 df.empty 视为预估失败并显式抛出异常，而不是返回 0；

    只有在确认 COUNT(*) 正常返回一行一列时才转换为整数。示例：

    if df is None or df.empty:
    raise RuntimeError("estimate_row_count returned no COUNT(*) result")
return int(df.iloc[0, 0])

    模拟 self._execute(template, sql, bind_params, timeout_ms=timeout_ms) 在 COUNT(*) 场景下返回空 DataFrame：调用 export_query(template_id) 提交一个实际会扫描大量数据的 detail 导出，请验证接口返回 400 的“Unable to estimate...”错误，而不是继续创建导出任务。
