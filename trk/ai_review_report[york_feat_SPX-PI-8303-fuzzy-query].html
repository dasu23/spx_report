    一旦 ShardingSphereDataSourceFactory.createDataSource(...) 的行为与原 HikariDataSource 不完全兼容，整个 tracking-api 的数据库访问都会在运行时一起受影响，可能表现为启动失败、连接属性失效、读写行为偏差或核心查询链路不可用，属于由配置层改动直接放大的服务可用性风险。

    至少在 MultiDataSourceConfig 中增加配置开关，允许快速回退到直接返回 trkDataSource 的旧实现。示例：

private boolean shardingEnabled;

@Primary
@Bean(name = "trkDataSource")

    // ...保留现有 Hikari 配置
    if (!shardingEnabled) {
        return trkDataSource;
    }
    Map<String, DataSource> dataSourceMap = new HashMap<>();
    dataSourceMap.put("tracking_backend", trkDataSource);
    dataSourceMap.put("tracking_backend_ds_0", trkDataSource);
