    tracking-api/src/main/java/io/speedx/trk/api/aop/KafkaConsumeLogAspect.java1 Critical1 个问题
    CRITICALL30-35安全风险
    问题

    KafkaConsumeLogAspect.around 在所有 @KafkaListener 方法外层统一记录 pjp.getArgs()，并通过 toJson 将完整消息体序列化后写入 info/error 日志。

    Kafka 消费参数通常直接承载业务消息原文，这里没有对字段做脱敏、截断或白名单过滤，新增代码会把任意消费消息内容落盘到日志。

    后果

    只要任一 @KafkaListener 消费的消息中包含运单信息、地址、手机号、签收图片地址、第三方回调凭证或其他敏感字段，这些数据就会被批量写入日志系统；

    拥有日志读取权限的人员或下游日志平台都可间接获取原始消息内容，形成敏感数据泄露面，且异常分支同样会泄露失败消息内容。

    怎么改

    将 KafkaConsumeLogAspect.around 的日志改为只记录必要的元数据，不要直接记录 pjp.getArgs() 的完整序列化结果；至少按消息类型做字段白名单和敏感字段脱敏，并限制日志长度。

    可优先改成仅记录 topic、group、消息类型、业务唯一键等非敏感字段。

    log.info("kafka consume success, topic={}, group={}, cost={}ms, payloadType={}",
        topic, group, System.currentTimeMillis() - start,
        pjp.getArgs() != null && pjp.getArgs().length > 0 && pjp.getArgs()[0] != null
