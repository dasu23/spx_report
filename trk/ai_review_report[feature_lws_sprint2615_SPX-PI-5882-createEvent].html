    问题

    KafkaConsumeLogAspect.around 在进入所有 @KafkaListener 方法时，直接把 pjp.getArgs() 经过 toJson 序列化后写入日志，新增代码 String args = toJson(pjp.getArgs()); 会把 Kafka 消息体中的全部字段原样落盘，且该切面对所有消费者统一生效，没有看到任何字段脱敏、白名单筛选或长度限制。

    后果

    只要任一 Kafka 消息中包含手机号、地址、token、内部业务参数或其他敏感字段，这些内容就会在成功和异常两条日志中被批量泄露；

    攻击者或低权限运维只需读取应用日志即可获得原始消息数据，泄露面覆盖所有新增接入的 @KafkaListener 消费链路。
