    问题

    config/proxy.ts 为 /cdn-pod/ 新增了动态代理，router 直接从 req.path 解析 host 并拼接成 https://${host}/ 作为目标地址，没有任何白名单、格式校验或固定域名限制。

    也就是说，请求路径首段可以控制代理实际访问的主机。

    后果

    只要有人能让前端发起 /cdn-pod/<任意host>/<path> 请求，开发/测试环境的代理就会替调用方向任意外部主机发请求，形成前端可触发的 SSRF/开放代理能力。

    攻击者可借此探测内网域名、访问本不该由浏览器直连的资源，或绕过浏览器同源限制读取被代理返回的内容。

    怎么改

    把 /cdn-pod/ 的 router 改成严格白名单映射，不要直接信任路径里的 host。至少应校验 host 只能命中预期的 POD 图片域名集合，未命中时拒绝代理；

    更稳妥的做法是前端只传资源标识，由服务端或固定映射决定真实目标域名。
