    CRITICALL95-98安全风险
    问题

    新增的 /cdn-pod/ 代理把 req.path 中用户可控的首段直接当作 router 的目标主机，const host = req.path.replace(/^\/cdn-pod\//, '').split('/')[0]; return https://${host}/; 没有任何白名单、格式校验或内网地址拦截，等于把开发/测试前端代理变成了一个可由请求路径驱动的任意 HTTPS 转发器。

    后果

    只要能访问前端开发或测试环境的人，都可以构造 /cdn-pod/<任意host>/<path> 请求，让代理代为访问非预期域名，甚至探测内网或云元数据地址对应的域名，形成 SSRF/开放代理 风险；

    同时 changeOrigin: true 会进一步降低目标站点基于 Host 的基础防护效果。

    怎么改

    把 router 改成只允许明确列出的 POD 图片域名，拒绝任何不在白名单内的 host；同时增加对私有网段、localhost、保留域名和异常字符的拦截，校验失败时直接返回固定的安全目标或拒绝请求。

    例如先解析 host，再用显式集合判断是否允许代理。

    怎么验

    在开发或测试环境访问 /cdn-pod/example.com/ 应仅在 example.com 被纳入白名单时成功；

    再分别访问 /cdn-pod/localhost/、/cdn-pod/127.0.0.1/、/cdn-pod/169.254.169.254.nip.io/、/cdn-pod/internal.service.local/，应全部被拒绝且不会向对应目标发起代理请求。
