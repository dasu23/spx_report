    CRITICALL95-98安全风险
    问题

    新增的 /cdn-pod/ 代理通过 router 直接从 req.path 提取 host 并拼接到 `https://${host}/`，没有任何白名单、格式校验或目标限制。

    这样会把前端请求路径中的首段主机名当作代理目标，形成可控的动态反向代理。

    后果

    只要开发或测试环境可访问该前端，攻击者就能构造 /cdn-pod/<任意主机>/<path> 请求，让本地开发机或测试网络代为访问内网地址、云元数据地址或其他受限主机，造成 SSRF 式网络探测与敏感资源访问风险；

    同时 changeOrigin: true 会进一步降低目标站点基于 Host 的基础防护效果。

    怎么改

    把 router 改成只允许预定义的 POD 图片域名集合，拒绝任意 host 透传；至少对 host 做严格校验并显式拦截内网地址、IP 字面量和非预期域名。

    示例：维护一个 const ALLOWED_POD_HOSTS = new Set([...])，在 router 中仅当 ALLOWED_POD_HOSTS.has(host) 时返回目标，否则直接抛错或返回一个不可达地址。

    怎么验

    在开发或测试环境访问 /cdn-pod/169.254.169.254/latest/meta-data/、/cdn-pod/127.0.0.1/、/cdn-pod/internal.service.local/health。

    期望代理层直接拒绝这些请求，而不是向对应主机发起转发。
