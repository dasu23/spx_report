    CRITICALL95-98安全风险
    问题

    新增的 /cdn-pod/ 代理把 req.path 中用户可控的首段直接当作 router 的目标主机，return https://${host}/; 没有任何白名单、格式校验或内网地址拦截。

    这样前端只要请求 /cdn-pod/<任意host>/<path>，开发/测试环境代理就会代表浏览器向该 <任意host> 发起服务端请求。

    后果

    这会把本地开发机或测试环境变成开放式 SSRF 跳板。攻击者可借助页面中可控图片地址或手工构造 URL，探测并访问内网地址、云元数据地址或仅代理机可达的管理端点；

    同时 changeOrigin: true 还会伪造目标 Host 头，放大对内网 HTTP 服务的访问能力。

    怎么改

    把 router 改成只允许明确白名单中的 POD 域名，禁止直接信任路径里的 host。

    至少同时做三层限制：校验 host 仅匹配预期域名后缀、拒绝 IP 字面量/localhost/私网网段、对非法值直接返回固定 target 或拒绝请求。例如：

    const ALLOWED_POD_HOSTS = new Set(['pod-cdn.speedx.io', 'pod-img.speedx.io']);

  }
  return `https://${host}/`;
}

    如果业务必须支持多 host，也应改为后端下发受控映射，而不是把完整主机名暴露为路径参数。

    怎么验

    在开发或测试环境访问 /cdn-pod/169.254.169.254/latest/meta-data/、/cdn-pod/127.0.0.1:8080/actuator、/cdn-pod/internal.service.cluster.local/health，验证代理当前会尝试把请求转发到这些非预期目标；

    修复后应全部被拒绝，仅允许预设 POD 域名。
