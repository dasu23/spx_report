    VintedApi.createShipment(String requestBodyJson) 在把 ERR_SHIPMENT_EXISTS 视为成功分支时，新增了 log.warn("Vinted create shipment ERR_SHIPMENT_EXISTS, rawResponse={}", resStr);。

    resStr 是 Vinted Carrier API 的原始响应报文，通常会包含运单号、收件人地址、pickup point 等业务敏感数据；

    这里在非异常但高频可触发的分支直接按原文写入 WARN 日志，扩大了敏感数据进入日志平台的范围。

    后果

    只要上游重复调用创建运单并触发 ERR_SHIPMENT_EXISTS，完整第三方响应就会被持久化到日志系统。

    具备日志读取权限的内部人员或外部日志平台一旦被误共享，即可批量获取运单相关敏感信息，形成不必要的数据暴露面。

    怎么改

    把 VintedApi.createShipment(String requestBodyJson) 的该条日志改为只记录必要字段，避免输出 resStr 原文；

    至少应只打印 response.getErrorCode() 和经过脱敏的业务标识。如果确需排障，建议增加受控的 DEBUG 日志并对运单号、地址、电话等字段做脱敏后再输出。

    怎么验

    构造一个返回 errorCode=ERR_SHIPMENT_EXISTS 且 rawResponse 中包含运单号、收件人地址或 pickup point 信息的响应，调用 VintedApi.createShipment(String requestBodyJson) 后检查日志，确认 WARN 日志不再包含完整 resStr，只保留 ERR_SHIPMENT_EXISTS 和脱敏后的必要标识。
