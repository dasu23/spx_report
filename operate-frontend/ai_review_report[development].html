    问题

    新增路由 /auth/admin-login 时没有在 config/routes.ts 上声明任何 access，并且注释明确说明“gated in the page by FEATURE:AUTH:ADMIN_LOGIN because route access cannot read tenant config before sign-in”。

    这意味着路由层面对未登录访问者完全放开，是否拦截只能依赖 auth/admin-login.tsx 页面组件内部自行判断；

    但该实现不在本分片 diff 内，无法证明页面首屏渲染、异步配置加载失败、或组件重构后仍能稳定阻断访问。

    后果

    任意未登录用户都可以直接访问 /auth/admin-login 并触发隐藏管理员登录入口的页面加载流程。

    只要 auth/admin-login.tsx 内部判断出现遗漏、闪屏暴露、异常降级或后续维护回归，这个本应受 FEATURE:AUTH:ADMIN_LOGIN 控制的入口就会被公开发现，扩大管理员认证面的暴露范围。

    怎么改

    把 /auth/admin-login 的访问控制前移到统一路由守卫或专门的匿名前置校验层，而不是仅依赖 auth/admin-login.tsx 页面内部判断；

    至少应在进入该路由前先完成 tenant config 拉取并基于 FEATURE:AUTH:ADMIN_LOGIN 决定是否允许渲染该页面。

    若当前框架限制无法在 access 中读取 tenant config，建议增加一个专用 wrapper component，在渲染 auth/admin-login.tsx 之前先做同步的 loading/deny 分支，避免页面内容先暴露再拦截。

    怎么验

    未登录状态下直接访问 /auth/admin-login：

    1. tenant 未开启 FEATURE:AUTH:ADMIN_LOGIN 时应在任何管理员登录表单渲染前被拒绝
    2. tenant config 拉取失败、超时或返回空值时也不应回退显示管理员登录入口
