    src/features/user/components/DrawerUserForm.tsx1 Major1 个问题
    🔒 安全/权限相关 · 1 项（点击展开）
    MAJORL415-416权限与访问控制
    问题

    DrawerUserForm 在编辑态把 editingRoleId 通过 params={{ includeRoleId: editingRoleId }} 传给 fetchVisibilityUserRoles(includeRoleId)，而 useUserRoles 会无条件把 includeRoleId 对应的角色并入 Role 下拉选项。

    这样一来，前端原本用 ROLE_VISIBILITY_MATRIX 对当前登录用户做的角色分配限制，在编辑已有用户时被主动放宽了。

    后果

    只要操作者能打开某个用户的编辑抽屉，且该用户当前角色不在操作者的可分配范围内，操作者就能在下拉中看到并保留该高权限角色；

    如果后端更新接口仅校验“可编辑该用户”而不再次校验“提交的 role 是否在当前操作者可分配集合内”，就会形成角色越权保留/变更入口，导致低权限管理员借编辑流程维持或提交本不应由自己分配的角色。

    怎么改

    把 includeRoleId 的用途限制为“仅用于当前值展示，不进入可选项集合”。

    可在 ProFormSelect 中单独注入当前值的 label，或将该选项标记为 disabled 且禁止切换到其他越权角色；

    同时要求提交前再次校验 role 是否属于 fetchVisibilityUserRoles() 的正常返回集合。

    怎么验

    准备一个当前登录用户角色为 Brokerage Admin 的会话，并打开一个 user.role 为 Branch View Only 的用户编辑抽屉。

    验证 Role 下拉是否把 Branch View Only 当作可选项返回；再尝试直接提交或先改其他字段后提交，确认前端与后端都会拒绝提交不在 Brokerage Admin 可分配范围内的 role。
