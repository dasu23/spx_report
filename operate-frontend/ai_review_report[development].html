    MAJORL274-278权限与访问控制
    问题

    新增的 /master-data/ports 路由未声明任何 access 权限控制，而同一段相邻的主数据页面如 carriers 明确使用了 access: 'MASTER_DATA:CARRIER:ACCESS'。

    这意味着前端菜单与页面访问层面对 master-data/ports 没有做与既有主数据模块一致的权限门禁。

    +      {
+        name: 'ports',
+        path: 'ports',
+        component: 'master-data/ports',
+      },
    后果

    只要用户已登录并能进入前端应用，就可能直接访问 /master-data/ports，看到港口主数据页面及其后续触发的数据请求。若后端接口权限配置不严，这会扩大未授权用户读取或操作主数据的风险；

    即使后端最终拦截，也会造成前端暴露受限功能入口，与现有主数据页面的权限模型不一致。

    怎么改

    给 config/routes.ts 中的 ports 路由补充与主数据模块一致的 access 权限码，并确保页面内的创建/编辑动作也复用同一权限体系。例如先新增专用权限码，再在路由上声明：

    {
  name: 'ports',
  path: 'ports',
  access: 'MASTER_DATA:PORT:ACCESS',
  component: 'master-data/ports',
}

    如果当前产品确实要求所有已登录用户都可访问，也应在需求与后端鉴权中显式确认，而不是以前端漏配权限的方式放开。

    怎么验

    准备一个没有任何主数据访问权限、但可以正常登录系统的账号。直接访问 /master-data/ports：修复前页面可打开；修复后应被前端路由拦截或重定向，且菜单中不显示该入口。

    再用具备 MASTER_DATA:PORT:ACCESS 的账号验证页面可正常访问。
