    问题

    AzureBlobMultiConfig.blobUtilMap(AzureBlobMultiProperties properties) 在 @RefreshScope Bean 重建时，会把新的 utilMap 和 domainMap 通过 BlobRefreshUtil.initMulti(...) 写入 BlobRefreshUtil 的全局状态，但这里没有看到任何同步、版本切换或原子替换保障。

    后果

    当 Nacos 配置热更新触发 blobUtilMap 重新初始化时，并发上传/生成 SAS URL 的线程可能拿到新旧容器映射混杂的数据，导致文件写入错误容器、生成错误域名 URL，进而造成文件访问失败或把业务数据写到错误的 Azure Blob 容器。

    把 BlobRefreshUtil.initMulti(...) 改为一次性原子替换完整快照，而不是分步写共享状态；

    如果 BlobRefreshUtil 内部维护静态 Map，应使用不可变对象封装后通过单次 volatile 引用替换，或在 initMulti 内部加锁并保证读路径也基于同一快照读取。
