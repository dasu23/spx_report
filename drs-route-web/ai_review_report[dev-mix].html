    问题

    get_standard_by_master_code 新增了 @router.get("/standards/{master_code}")，但整个函数只有 finally，没有像同文件 search_address_options 那样捕获数据库异常并转换为统一的 HTTPException。

    一旦 conn.cursor(dictionary=True) 或 cursor.execute(...) 因数据库错误抛出异常，异常会直接沿 FastAPI 默认链路返回。

    后果

    调用 GET /standards/{master_code} 时，攻击者只需构造触发数据库异常的请求或在数据库异常窗口访问该接口，就可能拿到未统一处理的内部错误响应，增加数据库表名、字段名或驱动异常细节暴露的风险，也会让该接口与同模块其它接口的错误契约不一致。

    怎么改

    在 get_standard_by_master_code 中补齐 except HTTPException: raise 和宽泛异常转换逻辑，避免底层数据库异常直接外泄；

    同时记录服务端日志，客户端仅返回通用错误信息，例如 raise HTTPException(status_code=500, detail="Internal server error")。

    怎么验

    模拟 get_db_connection() 返回的连接在 cursor.execute(...) 时抛出数据库异常，验证 GET /standards/{master_code} 返回的是统一的 500 通用错误，而不是包含底层异常细节的默认响应。
