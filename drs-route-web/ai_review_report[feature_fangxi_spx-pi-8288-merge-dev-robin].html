    MAJORL162-164安全风险
    问题

    _request_host 直接信任客户端可控的 x-forwarded-host，并把它传给 _cookie_domain 用于决定 response.set_cookie(..., domain=_cookie_domain(request)) 和 response.delete_cookie(..., domain=_cookie_domain(request)) 的 domain。

    当前代码没有校验 x-forwarded-host 是否来自受信反向代理，也没有与实际 host 做一致性校验。

    后果

    攻击者只要能直接访问 backend 并伪造 x-forwarded-host: anything.speedx.io，就能让 /api/v1/auth/browser-login 在响应里下发 Domain=.speedx.io 的共享登录 cookie；

    这会把原本应仅限当前主机的会话扩大到整个 speedx.io 父域，增加跨子域会话滥用和错误环境复用的风险。

    怎么改

    修改 _request_host，仅在确认请求经过受信代理时才读取 x-forwarded-host，否则只使用 host；

    更稳妥的做法是直接基于服务端配置的允许域名白名单决定 AUTH_COOKIE_DOMAIN，不要从请求头动态推导。示例：

    def _request_host(request: Optional[Request]) -> str:
    if request is None:
        return ""
    host = (request.headers.get("host") or "").strip()
    forwarded = (request.headers.get("x-forwarded-host") or "").split(",")[0].strip()
    if settings.TRUST_PROXY_HEADERS and forwarded in settings.ALLOWED_COOKIE_HOSTS:
        return forwarded
