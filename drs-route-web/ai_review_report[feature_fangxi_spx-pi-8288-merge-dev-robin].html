    MAJORL161-163安全风险
    问题

    _request_host 直接信任客户端可控的 x-forwarded-host，并把它传给 _cookie_domain 用于 response.set_cookie(..., domain=_cookie_domain(request)) 和 response.delete_cookie(..., domain=_cookie_domain(request))。

    在当前 diff 里没有看到任何对 x-forwarded-host 来源是否为受信反向代理、是否命中允许域名列表的校验。

    后果

    只要应用实例可被直接访问，攻击者就能伪造 x-forwarded-host 影响 AUTH_SESSION_COOKIE_NAME 的 Domain 属性，导致登录态 cookie 被错误地下发到非预期父域/子域，或让登出时删除不到真实 cookie。

    结果是浏览器会话边界被请求头驱动，可能造成跨子域会话泄露或残留会话无法清除。

    怎么改

    在 _request_host 中只在确认请求来自受信代理时才读取 x-forwarded-host，否则仅使用 host；

    同时在 resolve_auth_cookie_domain 调用前增加允许域名白名单校验，拒绝任何不在配置中的 host/domain。

    若无法建立可信代理链，直接移除对 x-forwarded-host 的依赖。

    怎么验

    构造一个直接访问 backend 的请求，携带 x-forwarded-host: attacker.example.com 调用 /api/v1/auth/browser-login，验证响应里的 Set-Cookie 是否出现 Domain=attacker.example.com 或其派生域；

    再调用 /api/v1/auth/browser-logout，确认是否因为请求头变化导致旧 cookie 未被删除。
