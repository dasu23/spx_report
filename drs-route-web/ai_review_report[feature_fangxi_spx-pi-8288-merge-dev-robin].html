    问题

    get_pickup_route_auto_sync_config 新增的异常分支把 SQLAlchemyError、RuntimeError、OSError 的底层错误原文直接拼到 HTTP 响应里：detail = str(getattr(exc, "orig", None) or exc)，随后 raise HTTPException(status_code=409, detail=detail)。

    这会把数据库驱动、文件系统或运行时异常中的内部实现细节直接暴露给调用方。

    后果

    当数据库连接失败、SQL 执行报错或底层 IO 异常发生时，任意能访问该接口的用户都可能看到数据库错误原文、表/字段名、连接信息或本地路径等敏感细节，攻击者可据此枚举内部结构并辅助后续攻击。

    怎么改

    把 detail 改为固定的业务错误文案，对真实异常仅记录到服务端日志，不要回传 exc.orig 或 exc 的字符串内容。

    例如返回统一的 "auto sync config unavailable"，并在日志中附带异常堆栈供排查。

    怎么验

    构造一次 SQLAlchemyError（例如让底层查询引用不存在的表或断开数据库连接），调用该接口并断言响应体 detail 不包含数据库驱动原文、SQL 片段、表名、文件路径或连接参数。
