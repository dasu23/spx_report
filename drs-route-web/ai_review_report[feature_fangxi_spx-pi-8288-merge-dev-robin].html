    问题

    get_pickup_route_auto_sync_config 新增的异常分支把 SQLAlchemyError、RuntimeError、OSError 的原始异常文本直接拼到 HTTPException(detail=detail) 返回给调用方，其中 detail = str(getattr(exc, "orig", None) or exc) 会优先暴露数据库驱动层 orig 的完整报错内容。

    数据库异常文本通常会包含表名、列名、约束名、连接目标等内部实现细节。

    后果

    任何能触发该接口异常的调用方都可以通过 409 响应枚举后端数据库结构和运行环境信息，为后续定向攻击提供侦察面；如果底层驱动把连接串片段或主机信息带进异常文本，还会进一步扩大敏感信息暴露范围。

    怎么改

    把 HTTPException 返回值改成固定的业务错误文案，不要把 exc.orig 或 exc 原样回传给客户端；详细异常仅记录到服务端日志，并确保日志里按需脱敏。可改为类似：

    except (SQLAlchemyError, RuntimeError, OSError) as exc:
    logger.exception("get_pickup_route_auto_sync_config failed")
    raise HTTPException(status_code=409, detail="获取自动同步配置失败") from exc
    怎么验

    构造一次数据库约束错误或连接错误，调用对应接口并断言响应体 detail 不包含具体表名、SQL 片段、数据库主机、驱动异常类名等内部信息；同时确认服务端日志仍能看到完整堆栈。
