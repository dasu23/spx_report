    问题

    TtInboundLogAspect.requestHeaders() 新增了对 HttpServletRequest 全量请求头的采集，并通过 ttApiLogger.log(...) 持久化入库；

    当前代码对 header 名称没有做白名单限制，注释里仅说明 TtApiLogger masks the credential headers，但这层切面本身已经把所有来路 header 原样汇总到了 headers。

    这会把 Authorization 之外的敏感头一并落库，例如网关透传的签名头、会话标识、自定义内部凭证头、真实来源 IP 链路头等，且是否被脱敏完全依赖另一个组件实现。

    后果

    只要 TT 入站请求携带新的敏感 header，TtInboundLogAspect 就会在未显式审计该 header 是否应保存的情况下把它写入日志链路；

    一旦 wms_tt_api_log 被运维、开发、审计平台或下游导出访问，可能造成凭证或基础设施元数据泄露，扩大横向移动和重放攻击面。

    怎么改

    把 requestHeaders() 改为显式白名单采集，只记录排障必需的非敏感头；不要依赖 TtApiLogger 兜底脱敏来保护所有未来新增 header。可按名称白名单保留如 Content-Type、User-Agent、X-Request-Id，其余直接丢弃或统一写成 ***。

    private static final Set<String> ALLOWED_HEADERS = Set.of(
        "Content-Type", "User-Agent", "X-Request-Id"
);

private Map<String, String> requestHeaders() {
    Map<String, String> headers = new LinkedHashMap<>();
    HttpServletRequest request = currentRequest();
    if (request == null) {
        return headers;
    }
    for (String name : Collections.list(request.getHeaderNames())) {
        if (ALLOWED_HEADERS.contains(name)) {
            headers.put(name, String.join(", ", Collections.list(request.getHeaders(name))));
        }
    }
    return headers;
}
