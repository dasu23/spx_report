    问题

    MessageTexts.render(Msg msg, Locale locale) 先通过 Object[] args = msg.getArgs(); 取得参数数组副本，但随后在 for 循环里把其中 Msg 类型参数原地替换成渲染后的 String。

    如果同一个 Msg 实例被多个线程或多次调用复用，这段逻辑会让一次渲染过程中得到的参数快照与后续调用的参数语义不一致，render 对嵌套 Msg 的处理依赖可变数组状态而不是纯函数输入。

    后果

    当上层把同一个 Msg 对象缓存、复用或在异常/日志/响应链路中重复传递时，不同调用之间可能出现语言结果不一致或调试困难的问题；这类可变状态还会放大并发场景下的不可预测性，导致操作员看到错误语言的消息内容。

    怎么改

    把 MessageTexts.render 改成不修改任何参数数组内容的纯函数：新建一个独立的 resolvedArgs 数组，把 Msg 参数渲染后写入 resolvedArgs，最后把 resolvedArgs 传给 SOURCE.getMessage(...)。

    例如：

    Object[] args = msg.getArgs();
Object[] resolvedArgs = new Object[args.length];
for (int i = 0; i < args.length; i++) {
    resolvedArgs[i] = args[i] instanceof Msg nested ? render(nested, locale) : args[i];
}
return SOURCE.getMessage(msg.getKey(), resolvedArgs, locale);

    同时补充复用同一个 Msg 实例分别调用 english() 和 render(Locale.CHINESE) 的测试，确保两次结果互不污染。

    构造一个包含嵌套 Msg 参数的 Msg 实例，例如 Msg.of("some.key", Msg.of("nested.key"))，先调用 render(Locale.ENGLISH)，再对同一个实例调用 render(Locale.CHINESE)；

    断言第二次返回仍按中文重新渲染，而不是复用第一次英文渲染后的参数状态。
