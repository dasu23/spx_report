    问题

    需求文档在「What Changes」第 1 点的「审计」明确要求“执行与取消均写 audit_log，含操作人、筛选条件、确认行数与原因”。

    DataPurgeService.execute(...) 的审计明细已写入 serviceId、logTimeFrom、logTimeTo、ruleAbbrs、loggers、confirmedRows、reason，但 DataPurgeService.cancel(...) 的审计只写了 Map.of("taskId", id)，没有把同一任务的筛选条件、确认行数、原因带入审计内容。

    后果

    取消操作发生后，audit_log 无法独立还原“取消的是哪一批日志、按什么条件圈定、原确认行数和原因是什么”，不满足需求要求的取消审计可追溯性。

    怎么改
