    问题

    RateLimitProtectAspect.release 对 redisKey 执行 decrement 后，再根据返回值执行独立的 delete，且未校验当前计数是否仍属于这次请求占位时的窗口。

    后果

    release 将计数减至 0 后，另一个同 bizKey 请求可以先 increment 并进入凭证校验，随后 release 的 delete 会删除该请求的占位，使凭证失败不再被计数。

    若原 redisKey 已过期，尚未完成的旧请求也会通过 release 扣减新窗口的计数，削弱并发场景下的防爆破限制。

    怎么改

    为 around 的占位记录关联计数窗口标识，并在 release 中使用 Lua 脚本原子校验窗口、扣减及必要时删除；旧窗口的请求不得修改新窗口计数。
